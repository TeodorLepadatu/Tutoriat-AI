# Loss Functions and Optimizers

## What is a loss function?

When building a ML model, a core step when wanting to improve it is measuring how wrong it is when trying to predict stuff on new, unseen data. We have 2 main ways in which we can do this:

1. Measuring it's accuracy on the unseen data (optional, but good for human visualization);
2. Measuring the **Loss** (mandatory!).

At its core, a loss function (often called a cost function or error function) is a mathematical way of measuring how wrong your machine learning model's predictions are compared to the actual truth.

To define one, you need to establish a formula that takes two primary inputs:

- The True Value ($y$): The actual label or target you are trying to predict.
- The Predicted Value ($\hat{y}$): The output generated by your model.

The function must output a single number (the "loss"). The worse the prediction, the higher the loss.

**Disclaimer:** You almost never invent a new loss function (unless you do research in ML). Instead, you define your problem and choose the standard loss function that actually fits it.

**For Regression** (Predicting continuous numbers, like house prices):
- Mean Squared Error (MSE): Punishes large errors heavily because it squares the difference.

$$MSE = \frac{1}{n} \sum_{i=1}^{n} (y_i - \hat{y}_i)^2$$

- Mean Absolute Error (MAE): Treats all errors linearly. Good if your data has outliers you don't want to over-penalize.

$$MAE = \frac{1}{n} \sum_{i=1}^{n} |y_i - \hat{y}_i|$$

**For Classification** (Predicting categories, like spam vs. not spam):
- Binary Cross-Entropy (BCE): Used when there are only two classes. It heavily penalizes confident but wrong predictions.

$$BCE = -\frac{1}{n} \sum_{i=1}^{n} [y_i \log(\hat{y}_i) + (1 - y_i) \log(1 - \hat{y}_i)]$$

- Negative Log Likelihood (NLL): The generalization of BCE.
 For a dataset of $n$ samples, where $y_i$ is the true class index for the i-th sample and $\hat{y}_{i, y_i}$ is the model's predicted probability for that specific correct class, the mean NLL is:

$$NLL = -\frac{1}{n} \sum_{i=1}^{n} \log(\hat{y}_{i, y_i})$$

*Remark*: BCE can accept random numbers as probabilities, but NLL needs these probabilities to sum up to 1. To make your probabilities sum up to 1, you need to apply the *Softmax* function to them:

For an input vector $z$ of $K$ real numbers, the Softmax function applies the standard exponential function to each element $z_i$, and normalizes these values by dividing by the sum of all these exponentials:

$$Softmax(z_i) = \frac{e^{z_i}}{\sum_{j=1}^{K} e^{z_j}}$$

**Other loss functions**:

- Hinge Loss (the loss function used by SVMs)

It ensures that the correct class score is higher than all other incorrect class scores by at least a fixed margin (in this case, a margin of 1).

For a single example $i$, the loss $L_i$ is defined as:
$$L_i = \sum_{j 
eq y_i} \max(0, s_j - s_{y_i} + 1)$$

Where:

$s_j$ is the model's predicted score for the incorrect class $j$,
 
$s_{y_i}$ is the model's predicted score for the true, correct class $y_i$.

$\max(0, \dots)$ clamps negative values to zero. If the correct class score ($s_{y_i}$) is greater than the incorrect class score ($s_j$) by the margin of 1, the loss for that class is 0.

- Full Dataset Loss with Regularization

To compute the overall objective function for training, the average loss across all training samples is combined with a regularization term.

$$L = \frac{1}{N} \sum_{i=1}^N L_i + R(W)$$

Where:

$N$ is the total number of samples in the dataset,

$L_i$ is the loss calculated for the $i$-th individual sample,

$R(W)$ is the regularization penalty applied to the weight matrix $W$ (e.g., L2 regularization). This term penalizes overly complex models (large weights) to prevent overfitting and improve generalization on unseen data.

## Optimizers: Minimizing the loss

Now that we have a loss function that outputs a number telling us how wrong our model is, we need a mechanism to systematically adjust the model's parameters to reduce that loss. This is the role of an Optimizer.

The most fundamental optimization algorithm is called **Gradient Descent (GD)**. All of the other optimization algorithms in ML are a derivation of GD.

Gradient descent works by calculating the gradient (the derivative) of the loss function with respect to the model's parameters. It then updates the parameters by taking a step in the opposite direction of the gradient, aiming for the lowest possible point (the minimum loss). This approach works, because by trying to make the derivative of the loss 0, we actually minimize the loss (see [Fermat's Theorem](https://en.wikipedia.org/wiki/Interior_extremum_theorem))

**The update rule and Learning Rate**

The size of the step the algorithm takes during each update is controlled by a crucial hyperparameter called the Learning Rate ($\alpha$). The general update rule for a parameter $x$ is: 

$$x_{new} = x_{old} - \alpha \cdot \nabla L(x_{old})$$,

where $\nabla L(x_{old})$ is the gradient of the loss function at the current position. If the learning rate is too small, the model will take a very long time to reach the minimum. If the learning rate is too large, the algorithm might overshoot the minimum and fail to converge (or even diverge, making the loss worse).

*Example: 2nd degree polynomial*:

Let's visualize this using a simple 2nd-degree polynomial as our "loss function": $f(x) = x^2$. We want to find the value of $x$ that minimizes $f(x)$. The analytical minimum is at $x = 0$. Let's see how gradient descent finds it iteratively.

The derivative of $f(x) = x^2$ is $f'(x) = 2x$.

Let's set the learning rate $\alpha = 0.1$ and a random starting point $x_{old} = 5$.

**Iteration 1**: Calculate the gradient at at $x = 5$: $2 \cdot 5 = 10$ and update the parameter $x_{new} = 5 - (0.1 \cdot 10) = 5 - 1 = 4$. 

**Iteration 2**: Calculate the gradient at $x = 4$: $2 \cdot 4 = 8$ and update the parameter: $x_{new} = 4 - (0.1 \cdot 8) = 4 - 0.8 = 3.2$.

We can see that $x$ is slowing going towards 0. This happens because we have chosen a good learning rate (lr). But what happens if the learning rate is too high?

Here is what happens if we change the learning rate to **$\alpha = 1.1$** while keeping the starting point at $x = 5$:

**Iteration 1:**

* Calculate the gradient at $x = 5$: $2 \cdot 5 = 10$
* Update the parameter: $x_{new} = 5 - (1.1 \cdot 10) = 5 - 11 = -6$
*(Notice it overshot the minimum of 0 and landed further away on the negative side)*

**Iteration 2:**

* Calculate the gradient at $x = -6$: $2 \cdot -6 = -12$
* Update the parameter: $x_{new} = -6 - (1.1 \cdot -12) = -6 + 13.2 = 7.2$
*(It overshot again, swinging back to the positive side, even further from the minimum)*

**Iteration 3:**

* Calculate the gradient at $x = 7.2$: $2 \cdot 7.2 = 14.4$
* Update the parameter: $x_{new} = 7.2 - (1.1 \cdot 14.4) = 7.2 - 15.84 = -8.64$

**Iteration 4:**

* Calculate the gradient at $x = -8.64$: $2 \cdot -8.64 = -17.28$
* Update the parameter: $x_{new} = -8.64 - (1.1 \cdot -17.28) = -8.64 + 19.008 = 10.368$

Because the step size is too large, the updates continuously overshoot the minimum at $x = 0$. The model gets progressively worse, violently oscillating between positive and negative values that grow toward infinity.
